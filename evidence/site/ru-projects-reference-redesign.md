## Scope and architecture

The change is limited to the Russian homepage Projects and Reference surfaces,
the 13 generated project-detail pages, their presentation metadata, scoped
styles, and validation. It does not change Chapters 1–24 educational source,
project behavior, accepted publication files, or formal M01 records.

Canonical project identity remains solely in
`manifest/projects_manifest.json`: project count, ID, slug, title, description,
source path, chapter, lesson, and route identity. The new
`manifest/projects_presentation.json` is keyed by canonical project ID and
contains only detail-page enrichment and local run guidance. It does not define
project membership, routes, source paths, or chapter/lesson identity. The
builder joins it onto the canonical manifest, and the validator rejects missing
or orphan presentation IDs, duplicate canonical IDs/slugs, and duplicated
canonical identity fields.

The accepted PDF/EPUB project appendix is isolated from the web presentation
through an inert publication-source template. The publication extractor keeps
receiving the exact accepted legacy fragment while browsers receive the new
single-H1 project layout. Six stored `publication_practice_title` values are
compatibility labels for the already-accepted appendix; they do not define
project identity or visible web-page facts.

## Known limitations and unresolved items

The repository does not currently provide valid standalone destinations for
every illustrative reference-card idea in the design brief (for example, lists
of figures/tables/listings or an RDF page). Those routes were not fabricated.
The four existing informational destinations and PDF/EPUB downloads are
preserved, and two verified chapter destinations were added, for eight real
reference cards total.

No local implementation issue remains. Product Owner visual approval is still
required; the pull request must remain unmerged until that review is complete.
