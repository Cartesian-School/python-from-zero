## Confirmed defects (discovered → classified → fixed → validated)

### BLOCKER

**F-001 (Chapter 17) — real project-source bug breaking 21 of 26 chapter screenshots.** `TicTacToeApp.__init__` created its `status_var`/`score_var` `tk.StringVar()`s with no `master`, which under a bare Xvfb display silently produced blank labels — every screenshot generated by `scripts/generate_chapter_17_outputs.py` showed no status/score text, and five files were byte-identical duplicates (`scoreboard.png` ≡ `empty-board.png` ≡ `new-round.png` ≡ `new-match.png` ≡ `x-turn.png`; `tic-tac-toe-pro.png` ≡ `mid-game.png`). Initially suspected as a stale-asset artifact; re-running the generator reproduced the broken PNGs byte-for-byte, disproving that and exposing the real bug. Fixed by passing `master=root` to both `StringVar`s; all 26 assets regenerated and re-verified to show their claimed content (e.g. §17.22's accessibility claim, previously falsified by its own screenshot, now genuinely holds).

**F-001 (Chapter 19) — busy-loop game prototype that could not actually be played.** `snake_basic.py`'s `glavnyj_cikl()` (taught in §19.8, "запустите… управление стрелками") had no delay mechanism: measured at **14 ticks in 2.1 ms**, it exited with score 0 before a keypress was physically possible. Fixed by adding real pacing to both the project file and the chapter's embedded code listing (§19.13's real `screen.ontimer`-driven loop was already correct; only the earlier §19.8 prototype had the defect). Re-verified with a fresh timed measurement post-fix.

**F-001 (Chapter 20) — practice notebook taught the exact anti-pattern its own lesson warns against.** §20.19 spends a paragraph plus a `debug` callout on "build asset paths from `Path(__file__).resolve().parent`, never from the current working directory." The paired notebook's shipped cell built a path from `Path.cwd()`, commented that this was "independent of CWD" (false — proven by `cd`-ing to a different directory and showing the constructed path changes), and asserted `is_absolute()` as if that proved CWD-independence (it doesn't). Fixed by rewriting the notebook to *demonstrate* the failure honestly — it now `os.chdir()`s to a different directory mid-notebook and shows the `Path.cwd()`-derived path breaking while a properly-fixed `BASE_DIR` path does not, turning the former false claim into the chapter's actual teaching point.
