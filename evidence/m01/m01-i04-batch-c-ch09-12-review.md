## Confirmed defects (discovered → classified → fixed → validated)

### F-008a / F-008b (MINOR × 2, resolved) — Chapter 11, stale Python 3.14 error-message text
Two hashability-error code examples (`11-19-mnozhestva-operacii`'s set-literal example and `11-20-slovari-metody`'s dict-literal example) claimed the older, shorter error text `TypeError: unhashable type: 'list'`. Verified that Python 3.14 actually raises a longer, more specific message for these exact constructions: `TypeError: cannot use 'list' as a set element (unhashable type: 'list')` for a set literal, and `TypeError: cannot use 'list' as a dict key (unhashable type: 'list')` for a dict literal (the short form is only what `hash()` alone raises). Fixed both comments to the verified-accurate 3.14 text.

### F-009 (MINOR, resolved) — Chapter 11, non-demonstrative warning example
`11-23-vybor-struktury`'s mutate-during-iteration warning used `items=[1,2,3,4]`, removing even numbers while iterating. Verified this happened to still print the "naively correct-looking" `[1,3]`, because the specific value skipped by the iterator's index-shift (3) was itself odd and would have been kept anyway — the example failed to visibly demonstrate the described danger. Replaced with `items=[2,4,6,8]`, which now visibly leaves `[4,8]` behind despite every element matching the removal condition, genuinely demonstrating the pitfall.

### F-010 (MINOR, resolved) — Chapter 12, stale cross-reference
`12-14-zhurnal-i-korzina`'s Debug Lab cross-referenced the counter/accumulator-reset-inside-loop bug as appearing in "§12.5 и §12.6". Verified against the chapter's own section numbering (from its opener's `ChapterSectionLink` list) that §12.6 is `12-11` (the text analyzer), whose own Debug Lab is about a *different* issue (inconsistent word normalization) — it does not contain this bug pattern at all. The two sections that actually contain it are §12.2 (`12-08`, the bug's origin) and §12.5 (`12-09`, which explicitly cross-references §12.2). Corrected the reference to "§12.2 и §12.5".

### F-011 (MAJOR, resolved) — Chapter 12, three wrong values in one "deterministic" transcript
`12-11-analizator-teksta`'s terminal transcript for the text-analyzer project claimed `Символов: 35`, `Уникальных слов: 6`, and `Самое частое слово: 'is' — 2 раз(а)` for the input `"Python is great and python is fun"`. Direct execution of the exact stated code and text under Python 3.14.6 gives `len(text)==33`, `len(set(normalized))==5`, and `max(counts, key=counts.get)=='python'` (tied with `'is'` at count 2, but `'python'` wins as the first-inserted of the tied maximum) — all three transcript values were wrong. The corrected values (33/5/'python') already matched this project's own pre-existing, correct graders (`12-11.py`, `12-12.py`), independently confirming the fix. Corrected all three values in the transcript.

### F-012 (MAJOR, resolved) — Chapter 9, stale generated notebook
`notebooks/chapter-09/09-05-ugadaj-chislo.ipynb` was stale relative to its own canonical builder (`scripts/build_notebooks_ch09.py`), which already defines and calls an `input_setup()` mock-input helper for it — the committed file lacked it and failed with `StdinNotImplementedError` under standard automated execution, the same defect pattern found and fixed three times in Batch B's Chapter 8 (F-007).
