Домашний проект C: «Камень, ножницы, бумага»

Победителя раунда решает один словарь — кто кого побеждает; матч теперь заканчивается по ясному условию — до трёх побед.

Определение победителя раунда — только один из кусков логики игры (наряду со случайным ходом компьютера и подсчётом счёта матча ниже), но именно он умещается в одном словаре — кто кого побеждает:

rps.py
POBEZHDAET = {
    "камень": "ножницы",
    "ножницы": "бумага",
    "бумага": "камень",
}

def opredelit_pobeditelya(hod_igroka: str, hod_kompyutera: str) -> str:
    if hod_igroka == hod_kompyutera:
        return "ничья"
    if POBEZHDAET[hod_igroka] == hod_kompyutera:
        return "игрок"
    return "компьютер"
Словарь вместо девяти условий
Можно было бы написать девять веток if hod_igroka == "камень" and hod_kompyutera == "ножницы": ... — словарь POBEZHDAET делает то же самое в трёх строках и читается как обычное предложение: «камень побеждает ножницы».

Ход компьютера с проверяемой случайностью

Как и в генераторе историй, ход компьютера принимает необязательный генератор случайных чисел — это позволяет тесту проверить конкретный, воспроизводимый ход:

rps.py
def hod_kompyutera(rng: random.Random | None = None) -> str:
    generator = rng if rng is not None else random
    return generator.choice(VARIANTY)

Матч до трёх побед

Игра теперь заканчивается не только по слову «выход», но и когда одна из сторон набирает три победы — ясно определённое условие окончания, а не бесконечный цикл:

rps.py
POBED_DLYA_POBEDY_V_MATCHE = 3

while schet_igroka < POBED_DLYA_POBEDY_V_MATCHE and schet_kompyutera < POBED_DLYA_POBEDY_V_MATCHE:
    # ...раунд игры...
