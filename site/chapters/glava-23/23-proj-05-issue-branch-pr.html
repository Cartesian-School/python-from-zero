Глава 23 · Часть II · Планируем SafeSort на GitHub

Первый цикл: Issue → Branch → Pull Request

Issue → ветка → код и тесты → Pull Request → CI → слияние — цикл, который повторится 14 раз.

SafeSort · Часть 2 из 6
Git и GitHub→Планирование→Проект→Реализация→Тесты и CI→Релиз

Issue сформулирован — теперь разберём полный цикл его жизни, от постановки задачи до закрытия. Этот цикл повторяется для каждой из 14 задач SafeSort, начиная со следующей части главы.

Терминал
git switch -c feat/directory-scanner
# ...пишем код и тесты, коммитим изменения...
git push -u origin feat/directory-scanner
gh pr create --title "feat: add directory scanner" --body "Closes #1."
Closes #N в описании Pull Request закрывает Issue автоматически
Если тело Pull Request содержит фразу вида Closes #1, GitHub автоматически закрывает Issue №1 в момент слияния этого PR — вручную закрывать Issue не нужно. Именно так закрыты все 14 Issues репозитория SafeSort.

Следующая часть главы проходит этот цикл по-настоящему, шаг за шагом, для первой реальной задачи — сканера каталогов.
