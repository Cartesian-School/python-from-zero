GitHub: Issue, ветка и Pull Request

От формулировки задачи в Issue до предложения изменений через Pull Request — путь одного изменения на GitHub.

SafeSort · Часть 5 из 6
Git и GitHub→Планирование→Проект→Реализация→Тесты и CI→Релиз

История коммитов, сделанных до этого момента, пока существует только в локальном репозитории — на одном компьютере. git push публикует её на GitHub — там вокруг этой истории есть рабочий процесс для совместной разработки: Issue, ветка, Pull Request.

Этот этап целиком происходит на GitHub

Issue — формулировка задачи до кода

Issue — запись на GitHub, описывающая задачу, найденную проблему или предложение. Прежде чем писать код, полезно кратко сформулировать, что именно нужно сделать и как проверить, что это сделано — так выглядит настоящая форма создания Issue (ничего не отправлено, это просто интерфейс формы):

Ветка — изолированное место для изменений

Ветка (branch) — независимая линия истории, отходящая от main. Пока изменения делаются в отдельной ветке, основная ветка репозитория остаётся нетронутой и всегда содержит последнюю рабочую версию:

Терминал
git switch -c feat/duplicate-detection
# ...пишем код и тесты, коммитим изменения...
git push -u origin feat/duplicate-detection

Pull Request — предложение изменений

Pull Request (PR) — предложение перенести изменения из одной ветки в другую, обычно из рабочей ветки в main. PR не «сливает» код автоматически: он открывает изменения для просмотра, автоматических проверок (о них — на следующей странице) и обсуждения, прежде чем код попадёт в основную ветку.

PR можно открыть раньше, чем код готов полностью
Pull Request не обязан представлять уже законченную работу — его можно открыть раньше, чтобы обсудить подход или получить промежуточный отзыв, и явно пометить как черновик. Ожидание «пока всё не будет идеально» не единственный способ работать с Pull Request.

Коротко

  • Issue формулирует задачу до того, как написан код — так проще понять, что именно нужно сделать и как проверить результат.
  • Ветка изолирует работу над одной задачей, оставляя main нетронутой до готовности.
  • Pull Request открывает изменения для проверки и обсуждения перед слиянием в main — он не сливает код автоматически сам по себе.
