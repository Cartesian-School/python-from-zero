SQLite: первая база данных без отдельного сервера

Вся база данных — один файл на диске, а движок работает прямо внутри вашего приложения.

SQLite — реляционная база данных, устроенная иначе, чем большинство других: она не запускается как отдельная программа-сервер, к которой приложение подключается по сети. Вместо этого вся база данных — это один файл на диске, а движок SQLite работает прямо внутри процесса приложения. Модуль sqlite3 входит в стандартную библиотеку Python — дополнительно ничего устанавливать не нужно.

Обычная клиент-серверная СУБДSQLite
Отдельный процесс-серверДа, работает постоянноНет — работает внутри процесса приложения
ХранениеУправляется сервером базы данныхОдин файл на диске
Настройка для стартаУстановить и запустить сервер, настроить доступНичего — файл создаётся автоматически
Несколько серверов приложения пишут одновременноШтатный сценарийОграниченная поддержка одновременной записи
«Простая» не значит «ненастоящая»
SQLite — не учебная имитация базы данных, а полноценный SQL-движок, которым пользуются даже очень крупные приложения — как основное хранилище локальных данных или как часть более крупной системы. Она хорошо подходит для локальных приложений, обучения, прототипов, тестов (раздел 22.33) и многих небольших и средних развёртываний, где её модель одновременного доступа достаточна. Клиент-серверная база выбирается не потому, что SQLite «не настоящая», а когда нескольким серверам приложения нужно надёжно писать в одну базу параллельно — раздел 22.24 разберёт эту разницу подробнее.

Подключение и курсор

podklyuchenie.py
import sqlite3

baza = sqlite3.connect("zadachi.db")
baza.row_factory = sqlite3.Row   # доступ к столбцам по имени

kursor = baza.execute("SELECT id, title FROM tasks")
for stroka in kursor:
    print(stroka["id"], stroka["title"])

baza.close()

sqlite3.connect(...) открывает (или создаёт, если файла ещё нет) файл базы данных. row_factory = sqlite3.Row позволяет обращаться к столбцам результата по имени, а не только по числовому индексу — удобнее и надёжнее, особенно если порядок столбцов в запросе когда-нибудь изменится.

Отдельное подключение на каждый поток
По умолчанию одно соединение sqlite3.connect(...) нельзя без осторожности использовать сразу из нескольких потоков. Раздел 22.29 покажет практичный способ организовать подключения во Flask-приложении — открывать соединение под каждый запрос и закрывать его сразу после.
